## 9.1 本章定位

前八讲的算法都是"单次求解"：一次对极、一次 PnP、一次 ICP。真实系统要**持续运行**：
帧不断到来——存哪、跟谁比、何时优化、地图怎么长、何时承认跟丢。本讲用约两千行
C++ 把前八讲的积木拼成一个能跑的 VO，并在"两两帧 → PnP 优化 → 局部地图"三级演进中
体会每个工程决策的动机。**这一讲是第 10–13 讲的宿主**：后端、回环、建图都往这个
骨架里插。

## 9.3 类结构与数据流

**五个类，单一职责**（书 §9.1）：

| 类 | 职责 | 关键成员 | 理论回引 |
|----|------|---------|---------|
| `Camera` | 内外参的持有与投影 | $K$、$T_{cw}$；`world2camera / camera2pixel` | (5.2)(5.3) |
| `Frame` | 一帧图像 + 特征 + 位姿 | id、`T_cw`、keypoints、descriptors | (2.2) 的"时刻 $k$"实体 |
| `MapPoint` | 路标：3D 位置 + 可信度 | $\mathbf{P}$、法向、观测次数、匹配率 | $\mathbf{y}_j$（D2-1）；位置由 (7.8) 三角化 |
| `Map` | 路标与关键帧的容器 | `insertPoint/removePoint`、活跃点查询 | 后端要优化的状态集合 |
| `Config` | 参数读取（文件 → 单例） | 路径、特征数、匹配阈值 | ——（工程） |

**数据流（每来一帧）**：

```
读帧 Frame ──→ 提取 ORB ──→ 与参考帧匹配 ──→ PnP 求位姿 T_cw
                                │                     │
                                │ (7.4) 匹配          │ D7-4 路线三（g2o 优化）
                                ▼                     ▼
                    参考帧更新 ◀── 三角化新点 (7.8) ── 地图更新 (筛选/插入)
```

## 9.4 三级演进与工程策略

### 9.4.1 第一级：两两帧 VO（书 §9.2）

每帧只与**参考帧**（上一关键帧）做匹配 + 求解：

```
算法 VO::addFrame(f):
  1. f 提取 ORB 特征
  2. match(f, ref_frame)                      # Hamming 最近邻 + 比值检验（D7 §7.4.1）
  3. 用 ref 的地图点做 PnP → T_cw             # D7-4 路线一（EPnP），给了初值
  4. 三角化 ref 新观测 → 新 MapPoint          # (7.8)
  5. 更新地图；若运动量/匹配数触发条件 → ref_frame ← f（关键帧切换）
```

*为什么只和参考帧比*：与历史全部帧比的代价 $O(N)$ 不可持续；参考帧 = "最近一次
确认可靠的观测基准"（依据：PTAM 的跟踪/建图分离思想，精读
[PTAM](../精读/PTAM_ISMAR2007.md)）。

### 9.4.2 第二级：用 g2o 优化 PnP（书 §9.3）

第一级的 PnP 用 EPnP 闭式解，噪声下并非最优。改进：以闭式解为初值，
按**图优化**再解一次（理论回引：(6.8) 顶点-边结构 + (4.11) 位姿雅可比 + 投影导数，
残差 $\mathbf{e} = \mathbf{u} - \pi(K, T, \mathbf{P})$ 即第 10 讲 (10.7) 的单帧版）。
*工程要点*：只优化当前位姿（路标固定为常值顶点）——"motion-only BA"，
等价于书 §9.3 的实现；这与 PTAM 跟踪线程的 motion-only G-N 跟踪同源
（`projects/slam/ptam/` 的 `track_motion_only` 有对应实现与测试）。

### 9.4.3 第三级：局部地图（书 §9.4）

只与参考帧匹配会在视角变化大时失配。改进：维护**局部地图**——当前位姿附近的
活跃 MapPoint 集合，匹配池从"参考帧的特征"扩大到"局部地图点"。
*MapPoint 生命周期策略表*（工程策略，无推导，每条给动机）：

| 策略 | 规则 | 动机 |
|------|------|------|
| 诞生 | 三角化成功且深度有效（(7.8) + 正深度检查） | 防病态深度（D7-3 讨论） |
| 提升 | 观测次数 ≥ 阈值（如 ≥ 2） | 单次观测的可信度不足 |
| 替换 | 新观测的深度更近/更准 → 更新位置 | 减少累积误差 |
| 剔除 | 匹配率 < 阈值 或 观测角超限 | 控制地图规模与质量 |
| 视野筛选 | 只取当前视锥内且距位姿 < $d_{max}$ 的点 | 匹配代价可控（投影预筛，回引 (5.3)） |

### 9.4.4 丢失检测与（本讲的）无解

跟踪内点数 < 阈值 ⟹ 丢失。本讲系统**只会退出**——重定位（拿新帧在关键帧库里
重识别）需要回环检测的词袋机制，第 12 讲补全；这也是书把"设计前端"独立成实践章、
把回环放在后面的叙事逻辑。

## 9.6 易错点与高频疑问

1. **参考帧 ≠ 上一帧**：跟丢恢复或运动剧烈时参考帧保持不动更稳（代码里是两个变量）；
2. **三角化没有角度下限**：近帧间基线小，(7.8) 病态，地图点深度抖动——设最小视差；
3. **地图点无限增长**：无剔除策略时内存与匹配代价线性膨胀；
4. **把 motion-only BA 当全局 BA**：前者只优化一帧位姿，快；后者见第 10 讲。
